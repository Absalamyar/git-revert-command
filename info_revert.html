دستور Git Revert چیست؟

دستور git revert برای لغو کردن تغییرات یک کات (Commit) مشخص استفاده می‌شود. ویژگی اصلی این دستور این است که تاریخچه (History) گیت را پاک نمی‌کند، بلکه یک کات جدید ایجاد می‌کند که دقیقاً عکس کات قبلی است. این کار برای پروژه‌های تیمی بسیار ایمن است.

چرا از Git Revert استفاده کنیم؟

  • امنیت بالا: تاریخچه کات‌ها حذف نمی‌شود و دیگر اعضای تیم دچار مشکل نمی‌شوند.
  • مناسب برای کات‌های عمومی: اگر کات شما روی سرور (مثل GitHub) فرستاده شده باشد، این بهترین روش است.
  • مستندسازی: در تاریخچه مشخص می‌ماند که چه تغییری و چرا لغو شده است.

طریقه استفاده (Syntax)

برای لغو یک کات، ابتدا باید شناسنامه یا همان شناسه (Hash ID) کات مورد نظر را پیدا کنید و سپس دستور زیر را اجرا کنید:

git revert [commit_id]

مثال عملی گام به گام

سناریو: فرض کنید شما کاتی انجام داده‌اید که باعث بروز خطا در برنامه شده است.

۱. ابتدا با دستور زیر لست کات‌های اخیر را می‌بینید:

git log --oneline

خروجی به این شکل خواهد بود:

a1b2c3d (HEAD -> main) اضافه کردن منوی جدید
e5f6g7h تغییر رنگ پس‌زمینه
9j8k7l6 ساختن صفحه تماس با ما

۲. حالا می‌خواهید تغییرات کات مربوط به منوی جدید یعنی a1b2c3d را لغو کنید:

git revert a1b2c3d

۳. بعد از اجرای این دستور، گیت یک ادیتور متن باز می‌کند تا پیام کات جدید را تایید کنید. بعد از ذخیره، کات جدیدی ساخته می‌شود که منو را حذف می‌کند بدون اینکه کات قبلی از تاریخچه پاک شود.

تفاوت اصلی Git Revert و Git Reset

  • Git Revert: تغییرات را لغو کرده و یک کات جدید می‌سازد (تاریخچه حفظ می‌شود).
  • Git Reset: کات‌ها را کاملاً از تاریخچه پاک می‌کند (برای کات‌های عمومی خطرناک است).
